# AGENTS.md

Instructions for coding agents (Claude Code, Codex, Copilot...) working in this
repository: a KiCad 10 project with a KiBot pipeline that generates the
documents and manufacturing files, locally with Docker and in GitHub Actions.

- Workflows and explanations: [docs/TEMPLATE_GUIDE.md](docs/TEMPLATE_GUIDE.md)
- Every setting, definition, profile entry and option:
  [docs/CONFIG_REFERENCE.md](docs/CONFIG_REFERENCE.md) (generated)

## Repository map

| Path | What it is | Edit it? |
| --- | --- | --- |
| `*.kicad_pro/sch/pcb/dru` (or `<board>/` in a multi-board repo) | The KiCad project | Yes, but close KiCad first; prefer KiCad for schematic/PCB changes |
| `kibot_settings.yaml` | Pipeline settings: status, image, CI, panel, variants, boards, libraries | Yes. Flat `key: value` only, shell scripts parse it |
| `kibot_yaml/kibot_main.yaml` | KiBot configuration; user parameters in `definitions:` at the end | Yes, the `definitions:` mostly. Comment every new definition |
| `kibot_yaml/kibot_out_*.yaml`, `kibot_pre_*.yaml`, `kibot_filt_*.yaml` | One KiBot output / preflight / filter per file, parametrized with `@NAME@` | When changing an output |
| `kibot_yaml/kibot_panel.yaml` | Second KiBot run on the panel PCB | Rarely |
| `kibot_resources/stackups/` | Stackup profiles (`--stackup`), design rules, fabrication notes | To add a manufacturer/process |
| `kibot_resources/scripts/` | Python helpers (stackup, checks, CI summary, changelog, reference) | Yes |
| `kibot_resources/templates/` | Report templates: fabrication/assembly notes, impedance table, README | Notes: yes. The impedance table and notes are rewritten by `--stackup` |
| `kibot_resources/fonts`, `colors` | Liberation fonts (Arial/Times metrics), KiCad color theme | No |
| `kibot_launch.sh` | Runs inside the container: all the generation logic | Yes, keep `bash -n` clean |
| `run_kibot.sh`, `run_kibot.ps1` | Host wrappers: start the container, manage library submodules | Keep both in sync |
| `.github/workflows/ci.yaml` | CI: PR checks, outputs publishing, releases on `x.y.z` tags | Yes, lint with actionlint |
| `.github/renovate.json` | Update PRs for the KiBot image and the actions | Rarely |
| `Diagrams/*.drawio` | Diagrams imported as pictures in the sheet of the same name (automatically before a generation when changed, or `--diagrams`) | Yes, in draw.io; then commit the updated sheet + `Diagrams/imported.json` |
| `CHANGELOG.md` | Keep a Changelog; the version and the revision history sheet come from it | Add entries under `[Unreleased]` |
| `docs/CONFIG_REFERENCE.md` | Generated reference | **Never by hand** |
| `README.md` | Regenerated by the pipeline in projects made from the template | **Never by hand** in a project |
| `Schematic/`, `PCB/`, `Manufacturing/`, `3D/`, `Images/*.png`, `Reports/`, `HTML/`, `KiRI/`, `Testing/`, `Variants/`, `index.html` | Generated outputs | **Never by hand, never commit them from a local run** (CI publishes them) |

## Commands

Docker is required. On Windows use `.\run_kibot.ps1` (same options) or Git Bash.

```
./run_kibot.sh -v DRAFT|PRELIMINARY|CHECKED|RELEASED [--log-dir kibot_logs]   # generate
./run_kibot.sh -v LITE                        # one assembly variant (KiCad 10 variant)
./run_kibot.sh --board hw/io                  # one board of a multi-board repo
./run_kibot.sh --stackup list|jlcpcb_4l|...   # apply a stackup profile (edits pcb/pro/dru)
./run_kibot.sh --init --project P --board B --company C --designer D --name file_name -y
./run_kibot.sh --diagrams [--fit]             # import Diagrams/<Sheet>.drawio|svg|png in the sheets
./run_kibot.sh --shell                        # shell in the container (kicad-cli, kibot, pcbnew)
./run_kibot.sh --help
python3 kibot_resources/scripts/gen_config_reference.py   # after changing a setting/definition/option
```

## Validating a change

1. `bash -n kibot_launch.sh` for the launcher; actionlint for the workflow:
   `docker run --rm -v "$PWD:/repo" -w /repo rhysd/actionlint:latest -no-color`.
2. `python3 kibot_resources/scripts/gen_config_reference.py --check` (the CI runs it).
3. Run the pipeline on a **copy** of the repository (outputs and the `.kicad_pro`
   text variables change during a run): `./run_kibot.sh -v CHECKED --log-dir kibot_logs`.
   Exit code 0 = all outputs generated, ERC/DRC and manufacturing checks without error.
   Read `kibot_logs/manufacturing_checks.md` and `kibot_logs/kibot_*.log`.
4. Look at the PDFs you touched (render a page with `pdftoppm` in the container).
5. Push a branch / open a PR: the check runs CHECKED and comments the results.

## Rules

- Don't commit generated outputs, KiBot logs or `kibot_????????.*` temporary
  copies. The launcher restores the `.kicad_pcb`/`.kicad_sch` after a run; the
  `.kicad_pro` text variables are updated on purpose.
- Close the board in KiCad before `--stackup` / `--init` (they edit the files).
- Keep `kibot_settings.yaml` flat and commented: the comment above a key is its
  documentation. Same for `kibot_main.yaml` definitions (inline or block
  comment), then regenerate the reference.
- Never put the literal `[skip ci]` in a commit message (it blocks the release
  of a tag pushed on that commit).
- The KiBot image is pinned (reproducible outputs): change it in
  `kibot_settings.yaml` only, check the outputs of the PR run.
- Paths in KiBot definitions are relative to the repository root, except the
  ones documented as relative to the project (`LOGO`); the output folders are
  relative to the output folder of the run (project, `<board>`, `Variants/<name>`).

## KiBot 1.9 / KiCad 10 quirks already handled

- `-g variant=X` must name a variant declared in the config before KiBot imports
  the KiCad 10 project variants: `kibot_main.yaml` declares a generic `kicad`
  variant named by `ASSEMBLY_VARIANT` (never name it `Default`).
- A `@NAME@` nested inside another definition ignores `-E NAME=` overrides: use
  it directly in the import mapping.
- KiCad variants drop the BoM `_mechanical` exclude filter (set explicitly) and
  KiRI crashes on variant runs (`variant_group` has no KiRI).
- KiBot DRC checks the zone fills stored in the PCB (`CHECK_ZONE_FILLS: false`):
  refill after changing clearances (`--stackup` does it).
- The cover page index reads the netlist XML: the launcher exports it before KiBot.
- `kicad-cli pcb render` ignores the zoom: no Z rotation for the KiCad angled views.
- A value overridden in a variant keeps the LCSC/MPN fields: override them too
  (the manufacturing checks warn).
